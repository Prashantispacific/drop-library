# Security Policy

## 🔒 Security Architecture (Strict BYOK)

Drop Library is designed from the ground up to be **100% public-repo safe** and private by default.

### Key Security Principles

1. **Client-Isolated Storage (Bring Your Own Key):**
   - No API keys, credentials, or personal tokens are ever stored in source control, environment files, or server configurations.
   - User Google AI Studio API keys are stored exclusively on the user's local device inside **IndexedDB** (`idb-keyval`).
   - IndexedDB is sandboxed by the operating system and browser under the Same-Origin Policy.

2. **Direct-to-Provider Communication:**
   - LLM requests generated by the official `@google/genai` SDK communicate directly from the client's browser/phone to Google's official API endpoints (`generativelanguage.googleapis.com`).
   - There is no intermediary proxy server logging, storing, or intercepting your API calls or API keys.

3. **Stateless Public Unfurler:**
   - The Netlify serverless unfurler (`netlify/functions/unfurl.ts`) is completely stateless. It accepts a public URL, queries OpenGraph and semantic HTML headers, and returns preview metadata.
   - It has no database connections, collects zero telemetry, and performs no tracking.

## 🛡️ Reporting a Vulnerability

If you discover a potential security vulnerability within Drop Library, please do **NOT** open a public issue.

Instead, please report it privately:
- **Email:** `prashantgautam9140@gmail.com`
- **Subject:** `[SECURITY] Drop Library Vulnerability Report`

Please include:
- A description of the issue and potential impact
- Steps to reproduce or proof-of-concept
- Suggested remediation (if known)

We will review reports promptly and publish patches responsibly.
